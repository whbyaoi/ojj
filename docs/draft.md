# 电子生命 Agent 设计文档（v0.1 复盘版）

> 标注约定：【已定】= 讨论中确认；【建议】= 我提出、待你确认；【待定】= 尚未收敛。
> 本文档只覆盖**结构性设计**，不含 prompt 工程与具体参数。

---

## 0. 设计原则

1. **不过度设计**：能简则简，延迟策略、IM 能力等先取最小可用版。
2. **结构化优先**：所有跨模块传递的数据用结构化字段，不用自由文本。
3. **确定性计算归代码，语义判断归 LLM**：衰减、状态流转、预算裁剪由代码执行；情绪增量、摘要、回复由 LLM 产出。
4. **缓存友好**：稳定内容前置，可变内容后置；裁剪有固定顺序。
5. **只追加、可回滚**：自我认知、记忆以追加为主，压缩点受控且可追溯。

---

## 1. 事件总线

### 1.1 事件字段（最小集）【建议】

| 字段 | 说明 |
|---|---|
| `id` | 全局唯一 |
| `timestamp` | 事件发生时间（非入队时间） |
| `source_channel` | 来源渠道（QQ群/私聊/系统心跳/内部…） |
| `source_entity_id` | 来源实体稳定 ID（人际关系系统依赖） |
| `event_type` | 消息/心跳/工具回调/系统事件… |
| `raw_text` | 原始文本 |
| `context_desc` | 结构化上下文：何时/何地/何人/何物 |
| `action_level` | 必须回复 / 可回复 / 不回复 |
| `perception_level` | 进上下文 / 仅进状态 / 完全丢弃 |
| `process_status` | pending / processing / done |
| `related_event_ids` | 可选，用于聚合/引用回复 |

> 约束：`context_desc` 用固定模板结构化，不用自由文本。

### 1.2 事件分级（两个正交维度）【已定 + 建议】

- **行动维度**：必须回复 / 可回复 / 不回复
- **感知维度**：进上下文 / 仅进状态 / 完全丢弃

**关键区分**：不回复 ≠ 不感知。群聊插嘴默认 = 不回复 + 仅进状态（更新情绪与记忆，不进本轮 LLM 上下文）。

> 该分级同时复用为**延迟策略的紧急度**，两者是同一套东西，不做两套。

### 1.3 延迟与汇总【已定：简单定时延迟】

- 首版：固定定时延迟，汇总一批事件后统一送 agent。
- 汇总时做一次**预处理 LLM 调用**：输入（事件批 + 当前情绪状态），输出（**摘要 + 情绪增量**）。
- 【建议】后续可升级为按 `action_level` 分级的延迟，但首版不做。

### 1.4 并发语义【必须定】

- **串行语义**：agent 一轮循环期间，新事件只排队不打断；本轮终止后重新汇总下一批。
- 队列设上限 + 溢出策略（丢弃最旧 / 合并 / 拒绝）。

### 1.5 持久化与恢复【必须定】

- 事件持久化，带 `process_status`。
- 进程重启后：`processing` 状态的事件回滚为 `pending`，避免重复回复或丢失。

## 2. Agent 循环

### 2.1 循环结构【已定】

- pi-agent 循环：工具调用 → 解析 → 继续，直到**无工具调用**或**特殊工具返回**（提交回复 / 进入休眠）时停止。
- 特殊工具语义需明确定义（提交回复？休眠？）。

### 2.2 终止兜底【建议】

- 最大轮数 / 最大 token / 超时三重限制。
- 工具失败降级路径。
- 循环中状态漂移检测。

### 2.3 上下文预算与裁剪【必须定】

**结构**：
```
[ 前缀区：人格设定 + 工具定义 ]  ← 稳定，永不裁剪，吃缓存
[ 可变区：情绪 + 关系摘要 + 记忆N条 + 事件汇总 + 循环历史 ]
```

**裁剪顺序**：先砍记忆条数 → 再砍低紧急度事件内容 → **人格与工具定义永不砍**。

> 硬约束：注入顺序固定，否则前缀抖动破坏缓存。

## 3. 拟人系统

### 3.1 情绪系统【已定：基于 LLM 的状态机 + 衰减】

- **转移函数**：LLM 输出"事件 → 状态增量"，**合并进 1.3 的预处理调用**，不单开 LLM 调用。
- **状态表示**：固定维度数值向量（如 valence/arousal 或自定义情绪轴），非自由文本。
- **衰减**：由**代码**按显式公式计算（向基线回归），LLM 不参与。
- **输出接口**【待定】：只进 prompt，还是也调制检索权重 / 回复延迟 / 主动发起？

### 3.2 记忆系统【已定：RAG + 主动回忆】

- 每次自动检索若干条；提供主动回忆工具。
- **写入侧**【建议】：全量入库 + 重要性评分，避免噪音淹没。
- 检索时机：预处理阶段还是循环内【待定，影响缓存】。

### 3.3 自我认知系统【已定：追加式 + 定期总结】

- 结构：**基线（summary）+ 增量追加日志**。
- 触发：条目数 / token 阈值。
- 总结生成新基线后，**旧基线归档保留可追溯**，增量日志清空。
- 护栏：只追加不覆盖；总结由主 agent 工具或独立后台任务执行【待定】。

### 3.4 人际关系系统【已定：允许演化】

- 以 `source_entity_id` 为键维护关系状态。
- 演化通过受限工具修改（见 3.5 护栏）。

### 3.5 自我修改护栏【建议】

- 修改分两类：叙事文本（日志式追加）/ 数值（受限工具）。
- 频率上限、留痕、可回滚、必要时二次确认。

### 3.6 系统间耦合【待定】

- 情绪 → 记忆写入权重？情绪 → 检索排序？关系 → 情绪基线？
- 是否共享统一"当前状态"结构（利于缓存与一致性）。

### 3.7 环境识别系统【待定】

- 尚未展开，需定义输入（渠道环境、时间、在场实体）与输出形态。

## 4. 输出能力层

### 4.1 抽象动作能力层【已定 + 建议】

内部定义标准动作，映射到具体 IM，避免与 QQ 绑定：

- 首版动作：**文本消息 / 图片消息 / 文件消息**。
- 引用回复：事件带 ID，LLM 可选引用（工具可选参数）。
- IM 特殊能力（加群退群等）**不纳入**。
- 能力可用性（权限/频控）在能力层表达，如主动发消息受 QQ 限制。

### 4.2 主动发起【待定】

- 心跳激活时想说话的路径。
- 主动发起的频控与拟人节奏（非秒回）。

---

## 5. 生命周期与心跳

- **心跳事件**【已定】：无外部事件时定时激活 agent。
- 【建议】两级心跳：轻量检查（规则/小模型）决定是否唤起完整 agent，避免空转成本。
- 心跳事件打标记，**不写入记忆**。
- 离线期间事件：积压队列 + 上限策略（见 1.4）。

---

## 6. 可观测性【建议】

- 总线消息日志、每轮 prompt/响应快照、五系统状态时间序列。
- 从第一天起建，否则拟人系统复杂后无法调试。

## 8. 建议实施顺序

1. **先闭环**：1.4 并发语义、1.5 持久化、2.3 预算裁剪 —— 三个小硬约束，定了总线与循环即闭环。
2. **再定耦合**：3.1 情绪接口 + 3.6 系统耦合 —— 定了其余模块接口自然收敛。
3. **后做演化**：3.3 自我认知压缩与护栏。
4. **其余随实现补**：引用回复、主动发起、环境识别。
